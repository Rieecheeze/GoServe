# Student department

The requested showcase Student belongs to College of Computer Studies (`DEP-CCS`). This is an affiliation, separate from a Staff office assignment or capability. Existing `offices` already contains the verified department catalog entry. Course/program, year level and institutional ID remain separate data; none are inferred from CCS.

The CLI-generated tenth core migration adds one nullable foreign key on `profiles`, with a `DEP-` catalog constraint. Existing profiles, roles, office IDs, capabilities, Terms, versions and completion state are preserved. The migration itself creates no users and backfills no departments. Existing table grants and own-profile RLS also protect the new column; authenticated clients have no direct profile update grant. Existing `update_account` source validates a fixed student-field set, preserves department and rejects injected assignment fields. Trusted administration assigns `DEP-CCS` to the reviewed demo Student.

Apply the additive migration before deploying a reader that requires the field. The new Android reader treats an omitted or null field as unknown, allowing an overlap with the earlier v2.3 account backend. Earlier readers ignore the additional nullable account response property. `account_view` already returns the profile row, so its signature does not change. No provider setting or Auth schema changes are needed.

Validate the six local SQL cases with `node --wasm-num-compilation-tasks=1 --max-old-space-size=384 --test backend/tests/profile-department.test.mjs`. They exercise preservation, trusted CCS assignment, client denial, catalog constraints, existing profile updates and cross-account read denial. Native account integration checks exercise parsing, earlier-response compatibility and malformed affiliation rejection. Synthetic profile/course/Terms fixtures must never be installed in the live project.

Rollback the reader first and retain the nullable column, data and access controls. No data contraction is necessary. Before any later column removal, export trusted assignments and inspect dependencies; do not drop populated profile metadata as an automatic rollback.
