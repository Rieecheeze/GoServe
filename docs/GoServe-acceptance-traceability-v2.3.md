## Evidence rules

| Code | Evidence required | Boundary |
| --- | --- | --- |
| U | Local native/domain or Edge/adapter unit checks | Injected Auth, network, parser and Storage boundaries do not prove live services. Preview/layout checks do not prove persisted workflows. |
| S | Executed PostgreSQL migration, constraint, transaction, function, grant and RLS assertions | Record package and PostgreSQL versions. PGlite fixtures for Auth/Storage/publications do not prove Supabase service integration or concurrent sessions. |
| R | Real authorized and unauthorized Supabase role sessions | Prove database, trusted operation, private Storage and Realtime behavior using independent accounts. |
| C | Real simultaneous sessions and retry/order tests | Prove uniqueness, locking, capacity and atomicity under competing transactions. Serial retries alone are insufficient. |
| D | Installed Android device/build evidence | Record API/device, lifecycle, keyboard/insets, accessibility and Light/Dark behavior. Robolectric and Figma are supporting evidence. |
| P | Approved provider or recovery-mail integration evidence | Record the approved contract/version, sanitized requests/outcomes, callback/reconciliation or recovery context. Credentials and browser returns are insufficient. |
| K | Actual Storage deletion and cleanup evidence | Verify object absence, scheduling, retry/audit and independent financial retention. Mocked removal/listing is supporting evidence. |

Every row is Pending until all required evidence is linked and reviewed. A local passing result may close its own U/S subcheck without closing the release row. A missing external input keeps the affected operation unavailable and the row Pending. Record a known limitation or failed result explicitly; do not replace it with a fixture result.

For each execution, record AT ID, date, source revision, Android build variant, environment and PostgreSQL version, synthetic account roles/offices/capabilities, device/API where applicable, expected and actual result, evidence path and remaining limitations. Exclude passwords, tokens, pickup codes, private documents and real student information.
