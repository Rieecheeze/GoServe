## Completed changes

Seryo is GoServe's app-focused persona/agent powered by the existing eGovAI API. A separate custom engine is optional. The user's identity instructions are stored server-side, identity questions are answered locally, and provider identities are blocked in chat output. Only fixed supported service-intent sentences and approved public catalogue facts reach the provider; raw messages and private profile/payment/request records are not forwarded. Input and output checks supplement that structural boundary. Current account, profile, Terms, separate AI consent, department scope, cleanup and dispatch limits remain enforced. Consent is checked again after generation. Chat stays in active session memory; user file analysis remains disabled pending a safe provider upload/deletion contract. The separate privacy notice retains accurate provider-processing disclosures.

eGovPay now has request-method selection, a native test checkout screen, browser opening, callback-triggered authenticated provider verification and manual/foreground reconciliation. Checkout links are pinned to the observed test host and transaction UUID. Server-owned bindings fix owner, request, amount, PHP currency and merchant reference. A durable creation claim prevents duplicate provider creation after an ambiguous response. Ready checkouts resume after reopening the screen; cross-payment key reuse conflicts. Verified PAID updates the financial ledger and payment version once. A late payment is recorded without reopening a cancelled request. Browser returns and callback bodies cannot confirm payment. Unknown provider statuses remain unknown. A lost provider UUID still requires manual provider reconciliation because the documented API has no reference lookup or POST-idempotency contract.

Navigation captions and per-item labels are removed. Accessible destination names, tooltips, selected states, ripple feedback and 48dp touch targets remain. Icon centers and spacing are checked for student, office and teller menus at 320/360/390/600dp with doubled text. New payment controls use the shared button feedback. Seryo remains animated in chat; startup has no mascot.

## First app test

The live project currently has zero completed profiles, zero participant Terms acceptances and zero service catalogue entries. Those were not fabricated to bypass the app's safeguards.

1. Install the r2 APK or run the `android` project in Android Studio.
2. Sign in with the existing approved account, complete its profile and accept the displayed test Terms.
3. For Seryo, separately allow AI consent, then ask an app-service question.
4. An office demo account must create the intended test service and fee through its service editor. The CCS student contacts the CCS Secretary for department services.
5. Submit a required-fee PHP test request using eGovPay, prepare/open its test checkout, then return and check payment status. Never enter real payment details into a supervised test.

Provider callback signature/retry specifications and unverified terminal enums remain outside the supplied contract. They do not override the authenticated GET verification used here. No absolute no-leak or provider-retention guarantee is asserted.
